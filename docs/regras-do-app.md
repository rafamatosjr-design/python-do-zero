# Python do Zero — Regras do Projeto

## Objetivo
Este projeto é uma plataforma pessoal para aprender programação do zero até desenvolvimento Full Stack.

## Regra principal
O conteúdo pedagógico é definido pela documentação deste repositório.

O agente de programação não deve inventar, substituir ou reorganizar o currículo por conta própria.

## Estrutura principal

O aplicativo possui somente:

- Início
- Curso
- Tarefas
- Vídeos
- Anotações
- Progresso

## Regras de desenvolvimento

1. Antes de alterar código existente, verificar como ele funciona.
2. Não recriar o aplicativo quando uma alteração pontual resolver.
3. Não apagar funcionalidades funcionando.
4. Não alterar conteúdos de outras aulas sem solicitação.
5. Não renumerar aulas.
6. Não adicionar funcionalidades não solicitadas.
7. Reutilizar componentes existentes sempre que possível.
8. Manter código organizado e legível.
9. Corrigir erros encontrados somente quando relacionados à tarefa atual ou necessários para seu funcionamento.
10. Não fazer grandes refatorações sem solicitação.

## Curso

O curso possui 120 aulas divididas em 12 módulos.

O progresso principal é:

aulas concluídas / 120 × 100

Abrir uma aula não significa concluí-la.

A conclusão acontece somente quando o estudante utiliza a ação de marcar a aula como concluída.

## Perfil do estudante

O estudante começa sem conhecimento prévio de programação.

Todo termo técnico novo deve ser explicado antes de ser utilizado como conhecimento presumido.

As explicações devem ser:

- progressivas;
- claras;
- tecnicamente corretas;
- em português brasileiro;
- adequadas para iniciantes;
- sem infantilização.

## Estrutura pedagógica

Sempre que aplicável:

Conceito
→ Explicação
→ Exemplo cotidiano
→ Exemplo de programação
→ Código
→ Explicação linha por linha
→ Prática
→ Exercícios
→ Desafio
→ Revisão

## Exercícios

Não revelar imediatamente a solução.

Utilizar:

1. Ver uma dica
2. Ver segunda dica
3. Ver solução comentada

A solução deve explicar o raciocínio, e não somente apresentar código pronto.

## Código

Todo código apresentado como solução deve ser válido.

Exemplos propositalmente incorretos devem conter claramente:

EXEMPLO COM ERRO — NÃO COPIE COMO SOLUÇÃO

## Vídeos

Nunca inventar:

- links;
- URLs;
- IDs do YouTube;
- nomes de vídeos.

Utilizar somente vídeos registrados na documentação.

Quando não houver vídeo validado:

“Não há vídeo complementar selecionado para esta aula.”

## Segurança

Nunca colocar no código:

- senhas reais;
- tokens;
- API keys;
- credenciais;
- segredos.

## Escopo

Não adicionar sem solicitação:

- marketplace;
- pagamentos;
- ranking;
- moedas;
- comunidade;
- chat público;
- feed social;
- certificados;
- IA interna;
- execução remota arbitrária de código.

## Interface

Priorizar:

- simplicidade;
- legibilidade;
- responsividade;
- acessibilidade;
- navegação clara;
- foco visível;
- bom contraste;
- HTML semântico quando aplicável.

## Regra para agentes de IA

Antes de executar uma tarefa:

1. Ler este arquivo.
2. Ler a documentação específica mencionada na tarefa.
3. Examinar o código atual.
4. Alterar somente o necessário.
5. Testar a alteração.
6. Verificar se funcionalidades existentes continuam funcionando.

Em caso de conflito entre uma instrução genérica e a documentação específica do curso, não inventar uma solução. Preservar o projeto e sinalizar o conflito.
